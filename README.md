# Управляющий Telegram-бот

Это бот с кнопками в Telegram. Бот принимает команды только от `OWNER_ID`
в личном чате. Сообщения в целевые чаты отправляют подключённые личные аккаунты.
Добавлять самого управляющего бота в эти чаты не требуется.

## Что уже реализовано

- Меню: аккаунты, текст, ссылки/addlist, паузы, предварительный план, запуск,
  остановка, статус и журнал CSV.
- Несколько личных аккаунтов; можно выбрать участвующие аккаунты кнопками.
- Вход по номеру, коду и 2FA при необходимости.
- Импорт SQLite `.session` Telethon и Pyrogram, StringSession **Telethon**,
  полного Auth Key HEX + DC ID, JSON и TData в ZIP.
- Вступление по публичным, приватным ссылкам и addlist при запуске плана.
- Одна рассылка или повторение с указанной паузой.
- Шифрование сохранённых ключей сессий, API-параметров, текста и планов.
- Журнал отправок и остановка всей задачи при ошибке/ограничении Telegram.

## Запуск в PyCharm

### 1. Создай управляющего бота

В официальном [@BotFather](https://t.me/BotFather) отправь `/newbot`, задай имя
и username. Сохрани полученный токен. Не отправляй токен в этот чат или Git.

### 2. Открой проект и установи зависимости

Открой в PyCharm папку `E:\GPT\telegram_bot`.
Выбери интерпретатор Python 3.12 или 3.13, создай окружение `.venv`.
В Terminal в папке проекта выполни:

```powershell
python -m pip install -r requirements.txt
```

Если терминал использует другой Python:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Зависимости для локальной проверки также установлены в существующее окружение
`E:\GPT\telegram_sender\.venv`. Его можно выбрать как Existing Interpreter
(`Scripts\python.exe`), если не хочешь создавать второе окружение.

### 3. Настрой бота без параметров запуска

Открой `configure.py` → правая кнопка мыши → **Run 'configure'**.
В нижней консоли введи токен бота, свой Telegram ID и API ID/API Hash.
Для скрытого ввода токена/хеша в некоторых конфигурациях PyCharm потребуется
включить **Emulate terminal in output console**, либо выполнить
`python configure.py` во вкладке Terminal.

Если своего Telegram ID не знаешь, введи `0`. После запуска напиши своему боту
`/id`, останови программу, замени `OWNER_ID=0` в `.env` на полученный ID,
запусти снова. ID нужен от того аккаунта, которым ты будешь управлять ботом.
Это не обязательно ID аккаунта, который будет рассылать сообщения.

API ID/API Hash можно получить в [API development tools](https://my.telegram.org).
Они нужны для входа по номеру и импорта сессии/ключа без JSON. Можно пропустить
их при настройке, если сначала будешь загружать JSON с `app_id` и `app_hash`.
Токен BotFather и API Hash — разные значения.

`configure.py` создаст `.env` и ключ шифрования. При повторной настройке
существующий ключ сохраняется. Не теряй `ENCRYPTION_KEY`: без него сохранённые
аккаунты не прочитать. Файл `.env` не нужно отправлять в Telegram.

### 4. Запусти

Открой `main.py` → правая кнопка мыши → **Run 'main'**.
Параметры `--login`/`--send` здесь не используются. Поле Script parameters пустое.
Рабочая папка: `E:\GPT\telegram_bot`. Пока тестируешь, PyCharm должен оставаться
открытым и процесс должен работать. Не запускай одновременно вторую копию
с тем же BOT_TOKEN на BotHost.

Теперь открой созданного бота в Telegram и отправь `/start`.

## Как подключить аккаунт

Нажми **Добавить аккаунт** и выбери формат.

### Номер телефона

Введи номер в формате `+код_страны_номер`, затем код, затем 2FA при запросе.
Бот покажет тип доставки кода, возвращённый Telegram. Он не гарантирует SMS:
способ доставки выбирает Telegram. Код может прийти в действующее приложение.
Telegram может отклонить номер/приложение или запрос кода; бот показывает имя
ошибки и останавливает этот вход. Смена интерфейса не устраняет такие ограничения.

### JSON

Загрузи свой JSON кнопкой «скрепка → Файл».

Если в JSON только `app_id`, `app_hash`, параметры устройства и пустое
`session_file`, бот прочитает настройки и попросит **следующим сообщением**
`.session` Telethon/Pyrogram или номер телефона. Имя файла из JSON не позволяет
боту забрать файл с твоего компьютера. Передай сам файл отдельно.

Поддержаны поля ключа `auth_key`/`auth_key_hex` + `dc_id`, строки
`session_string`/`string_session`, опциональные `user_id`/`id` для проверки.
Прокси из JSON сейчас не подключаются. TData импортируется отдельной кнопкой.

### Кнопки со скриншота

- **.session Telethon** — скачай и загрузи в одноимённый пункт бота.
  Это самый прямой вариант для первого теста.
- **.session Pyrogram** — загрузи в пункт Pyrogram. Поддерживается обычная
  SQLite-сессия, а не строка Pyrogram.
- **.json** — загрузи через JSON; если авторизации внутри нет, передай ещё `.session`.
- **TData** — упакуй одну папку TData с одним аккаунтом в ZIP (до 18 МБ),
  выбери TData ZIP. После загрузки пришли локальный пароль TData,
  либо `-`, если пароля нет. Это локальный пароль папки, а не пароль Telegram 2FA.
- **Auth Key** — скопируй ПОЛНЫЙ ключ, а не сокращённый текст с многоточием.
  Нужны 512 HEX-символов и DC ID. User ID необязателен и проверяется после входа.

Для Auth Key отправь JSON текстом:

```json
{
  "dc_id": 1,
  "auth_key": "ЗДЕСЬ_ПОЛНЫЙ_КЛЮЧ_512_HEX_СИМВОЛОВ",
  "user_id": 123456789
}
```

Номер телефона сам по себе не заменяет ключ. User ID сам по себе не авторизует.
Подключай только свои аккаунты. Для импорта существующей сессии останови другие
программы, которые используют именно эту сессию: один ключ с разных IP может
быть отозван Telegram. Аккаунт должен оставаться доступен его владельцу.

Сообщения с учётными данными бот пытается удалить после получения. Они всё равно
проходят через Telegram Bot API и твой хостинг; это не сквозное шифрование.
Сам импортированный ключ сохраняется зашифрованным в `data/bot.sqlite3`.

## Рассылка через кнопки

1. **Аккаунты** — выбери нужные (✅).
2. **Текст сообщения** — отправь текст объявления. Только текст, без вложений.
3. **Ссылки / addlist** — отправь ссылки по одной на строку или UTF-8 `.txt`.
4. **Паузы и повторение** — например `30 0`: 30 секунд между действиями,
   один цикл. `30 3600`: повторять через час после завершения цикла.
5. **Создать план** — бот проверит ссылки, покажет чаты и необходимые вступления.
   На этом шаге сообщения не отправляются и вступлений нет.
6. **Запустить** под планом — выполнит вступления и отправит сообщения.
7. **Остановить** или `/stop` — остановит задачу после текущего запроса.

Поддерживаются:

```text
@your_group
https://t.me/your_group
https://t.me/+private_invite_hash
https://t.me/joinchat/private_invite_hash
https://t.me/addlist/folder_slug
```

Используй чаты, где разрешено публиковать твои объявления. Вступление не даёт
права писать в канале: для публикации могут требоваться права администратора.
Если по ссылке отправлена заявка на вступление, нужно дождаться одобрения;
задача остановится с соответствующей ошибкой. Личные сообщения по username
и ссылки на отдельные сообщения не поддерживаются.

Каждый выбранный аккаунт отправляет во все чаты плана. Дубли ссылок на один чат
внутри одного аккаунта убираются. Если аккаунтов несколько, в одном чате может
оказаться по сообщению от каждого аккаунта. Автоматической ротации аккаунтов
для обхода ограничений нет; FloodWait/ошибка останавливают всю задачу.

Изменение текста/списка/выбранных аккаунтов не меняет уже созданный план.
Чтобы применить изменения, создай новый план. Повторяющаяся задача использует
зафиксированный список чатов: новые чаты из изменившейся папки сами не добавятся.

## Журнал, сбои и перезапуск

- `sent`: Telegram подтвердил отправку.
- `pending`: запрос начат, но подтверждение не сохранено; проверь сообщение
  вручную в Telegram. Это может быть ошибка или успешная отправка перед сбоем.
- **Статус → журнал нужной задачи** позволяет выгрузить CSV.
- После перезапуска процесс не начинает рассылку самостоятельно. Последняя
  работавшая задача становится `interrupted`. В статусе можно нажать «Продолжить».
- Продолжение пропускает `sent` и `pending`, чтобы не повторять неопределённую
  отправку. Циклы считаются с нуля; уже записанные циклы будут пропущены
  с обычными межцикловыми паузами. Для новой рассылки создай новый план.
- Не удаляй `data/bot.sqlite3` ради повторной отправки: там лежат и аккаунты.
- Удаление аккаунта из панели не отзывает его авторизацию в Telegram.

## Размещение на BotHost

Подготовленный `telegram_bot.zip` содержит код и зависимости, без `.env`,
аккаунтов и базы. В архиве есть `main.py`, `requirements.txt`, `bothost.json`
и Dockerfile с Python 3.12.

1. Останови локально `main.py` в PyCharm.
2. В профиле BotHost включи «Загрузка бота из архива».
3. В «Мои боты» выбери «Загрузить из архива», передай `telegram_bot.zip`.
4. Главный файл — **main.py**, язык Python. Введи токен от BotFather.
5. В переменных окружения укажи:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен управляющего бота |
| `OWNER_ID` | Твой Telegram ID, которым управляешь ботом |
| `TELEGRAM_API_ID` | API ID для входа по номеру/импорта без JSON |
| `TELEGRAM_API_HASH` | Соответствующий API Hash |
| `ENCRYPTION_KEY` | Ключ из локального `.env` или вывод `python setup_key.py` |
| `DATA_DIR` | `/app/data` |

6. Запусти деплой, дождись установки зависимостей и открой бота в Telegram.
7. Для переноса ранее подключённых аккаунтов останови оба процесса и загрузи
   содержимое локальной папки `data` в `/app/data` через файловый менеджер.
   Используй ТОТ ЖЕ `ENCRYPTION_KEY`. Без переноса базы просто подключи аккаунты
   заново через меню. Не загружай рабочую базу одновременно из запущенного процесса.

По документации BotHost загрузка ZIP сейчас доступна на «Базовом» и Pro.
При отсутствии этой функции можно разместить код в Git-репозитории и подключить
его к хостингу. Не включай в Git `.env`, сессии или папку `data`.

Источники BotHost:
[Загрузка архива](https://bothost.ru/docs/upload-bot-archive),
[переменные окружения](https://bothost.ru/docs/environment-variables),
[постоянное хранилище](https://bothost.ru/docs/database-storage).

## Проверка кода

```powershell
python -m unittest -v test_bot
```

Локальные тесты проверяют доступ владельца, шифрование, импорт структуры сессий,
защиту ZIP, планирование addlist, вступления, журнал и остановку по FloodWait.
Они не подключаются к Telegram. Живой вход и размещение на хостинге требуют
твоих учётных данных и ещё не проверены.
